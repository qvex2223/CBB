# Local toolkit — what is on this machine, and what policy still forbids

Answers one question: **can I run this command here, and where does it live?**

A skill that names a tool the box does not have is worse than a skill that names none —
`command not found` goes to stderr, the step is silently skipped, and the hunt continues
as if the check had been run. That failure is documented in this workspace's own history,
and it is the reason this file lists absence as loudly as presence.

> The tables below are **generated from live PATH** by `scripts/gen_toolstand.py`, not
> written by hand — the hand-written version drifted twice: it carried moved paths, and it
> listed `gf`, `assetfinder`, `gitleaks` and `subzy` as *not installed* while all four were
> on PATH, which is a standing instruction not to use a tool you have. Trust the block,
> and if you suspect it is stale run `python3 scripts/gen_toolstand.py --check`.

## Proxy + MCP — Caido

```bash
~/security-research/tools/caido/bin/caido-cli --listen 127.0.0.1:8080 --no-open --no-sync
cbh tools doctor                               # verifies the real tools/list handshake
node runtime/health.mjs --only=caido           # same check, caido alone
```

Caido v0.58.3, MCP server v4.3.0 (built from reviewed source), 66 tools under
`mcp__caido__*`. Proxy and UI both on `127.0.0.1:8080`; the wrapper is
`runtime/caido-mcp.mjs`, declared as `caido` in `.mcp.json`. Setup, provenance and the
account login: **`docs/caido.md`**. One Caido project per engagement —
`caido_create_project` / `caido_select_project`.

The proxy is for the **last mile** — redirect chains, cookie/session state across a flow,
replaying and mutating a captured request. Not for recon, where `bbcurl` is strictly
better because it carries scope, pacing and audit. Caido and Playwright reach the network
themselves, so `scripts/mcp-gate.py` applies the same scope/pacing/audit contract to their
send and navigate calls — including every request inside a `caido_batch_send`.

Gated harder than the rest, because of what these do:

| Tool | The rule |
|---|---|
| `caido_batch_send`, `caido_race_window_send` | up to 50 requests per call; needs `"allow_bulk_tools": true` in `profile.json`, and the pacing budget is paid per request. A batch needing >120s of waiting is refused with the size that fits. |
| `caido_automate_task_control` `action=start\|resume` | Caido's fuzzing engine — the broad automated scanning every engagement here forbids. Same `allow_bulk_tools` opt-in; prefer `caido_batch_send`, which is gated per request. |
| `caido_race_window_send` | raw sockets inside the MCP server, so **Caido's own history never sees these requests**. The `audit.jsonl` row is the only record. |
| `caido_forward_intercept`, `caido_run_workflow type=active`, `caido_edit_request` with no `host` | refused as UNVERIFIED — their arguments name no target the gate can check. Each refusal prints the way through. |

**Burp-only things that do not exist here.** Do not write a command around them:

| Burp feature a skill may mention | Here |
|---|---|
| Repeater | `caido_send_request` / `caido_edit_request` (Replay) |
| Intruder | `caido_batch_send`, or Automate under the bulk opt-in |
| Proxy history | `caido_list_requests` / `caido_get_request` / `caido_get_sitemap` |
| Collaborator | **nothing.** `interactsh-client` is the OOB channel, with the rules above |
| Burp extensions (HTTP Request Smuggler, Turbo Intruder, …) | no equivalent; `caido_race_window_send` covers single-packet races only |
| Passive/active scanner | not installed, and sweeps are forbidden anyway |
| Save request / saved-request store | `caido_create_replay_session` + collections |

Burp itself is **gone from this box** — `/opt/Claude/tools/burp` does not exist and
`scripts/burp-mcp.sh` is dead code. `mcp-gate` still covers `burpmcp` tool names in case
the stack ever returns, but do not plan a hunt around it.

## Re-audit after any workspace move or rebuild

```bash
cbh doctor                                     # hooks, skill copies, reward bands, PATH
python3 scripts/gen_toolstand.py --check       # these tables vs live PATH
python3 scripts/gen_toolstand.py --write       # refresh them after installing a tool
python3 -m unittest discover -s tests          # the enforcement layer
python3 engine/pacing.py --selftest
python3 engine/scope.py --selftest
```

Install path on this box (no `pip`, no `cargo`, no `docker`; release tarballs and
`curl | sh` are sandbox-blocked):

```bash
GOBIN=~/.local/bin GOPATH=~/security-research/tools/gopath \
  ~/security-research/tools/go/bin/go install <module>@latest
```

**After installing anything, do all three or it stays invisible:** add it to
`engine/workspace_check.py::TOOLS_REQUIRED`, add it to `FREE`/`RESTRICTED` in
`scripts/gen_toolstand.py` and `--write`, and — if it reaches the network — add it to
`engine/skill_signals.py::SENDER_RE`, or it fires at live targets with the gate blind to it.
